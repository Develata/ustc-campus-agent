# Server-configured model selection

Case: MODEL-001. Owner: bounded M50 provider catalog; M30 pins one selection per submitted turn. M10 and Web only project the catalog and submit its opaque ID.

## Contract

- The existing UCA_AGENT_* configuration remains the `default` entry and the default for legacy requests. Optional UCA_AGENT_MODELS_FILE names an operator-controlled JSON file, at most 64 KiB, closed schema `uca-agent-models/v1`, with a `models` array of at most 15 additional entries. Duplicate IDs (including default), fields, invalid profiles or credentials reject startup without fallback. Each entry has `id`, `label`, `mode`, and network entries also `base_url`, `model`, `api_key_file`, `timeout_ms`, `context_limit_tokens`. Modes reuse mock/local-chat/openai-compatible and existing provider validation. IDs are 1-64 ASCII alphanumeric/dot/dash/underscore; labels are nonblank <=128 UTF-8 bytes without controls. Mock entries cannot carry network settings. New network entries require an absolute api_key_file; legacy environment path behavior remains unchanged. The models file is a bounded regular file, rejecting symlink leaves and special files without blocking. Additional file-based profiles are currently admitted on Unix/Linux/WSL; non-Unix hosts reject that new file-loading profile explicitly while preserving the existing no-file default configuration. Errors expose only closed configuration categories. No new provider protocol or discovery network call is introduced.
- GET /api/v1/agent/models requires X-USTC-Client-Protocol-Major: 1 and projects `{schema:"uca-agent-models/v1",default_id:"default",models:[{id,label,provider:{mode,model},tool_calling,context_limit_tokens}]}` only. No endpoints, credential paths or keys are exposed. The legacy status query retains its default-provider meaning.
- Closed `ustc-agent-chat-request/v3` and `chat-conversation-turn/v2` accept a required string `model_id`, in addition to the previous request fields. Existing v1/v2 stateless requests and v1 saved turns retain their old schemas and implicit default behavior; smuggling model_id into old schemas rejects. Unknown IDs reject before provider/tool execution; no silent substitution. Prompt customization cannot set a model.
- A saved turn's full typed intent, including model ID when present, participates in idempotency. Exact terminal replay returns the original result even if that model is later removed (an independently deleted conversation remains inaccessible under conversation-management.md); changed selection under the same request ID conflicts. Legacy stored digests remain compatible. Provider selection is frozen for the entire running turn, independently across requests. Selecting another model never mutates global provider state or rewrites historical answers. Completed responses retain the actual provider/model identity. If executor construction fails after a new turn reservation, finish persists a terminal failure rather than leaving a running turn.
- The composer toolbar offers a keyboard-accessible model selector, describes public tool capability accessibly with a hover hint and in Settings, and remembers only the selected ID locally. Selection affects future sends; busy or uncertain submissions disable changes and retain their original serialized request for retry. Removed/stale selections require explicit reselection rather than silently substituting. A failed catalog load has a visible retry and prevents new submissions until confirmed. Old historical messages retain their returned provider identity.
- The settings page explains server-side configuration. A single configured model remains visible and selectable; no fabricated external models. Model registration is operator configuration, not a browser key/URL editor. No production per-user model entitlement, billing or automatic fallback is implied.

- The compact trigger opens a model menu with full display names, the selected checkmark and each model's tool/chat capability. Keyboard focus movement does not commit a selection; Enter/Space selects. Arrow keys and Home/End navigate, Escape restores trigger focus, Tab continues the normal focus path, and clicking outside or leaving Chat dismisses the menu. Loading, busy and uncertain states disable the trigger and menu items and close any open menu. A long or maximum-size catalog remains readable in a viewport-bounded scrollable menu, including mobile widths.

## Verification

Bounded configuration/secret redaction tests; actual HTTP provider peers proving selected wire model and distinct endpoints; legacy/default compatibility; unknown and old-schema rejection with zero provider IO; interleaved selections and exact saved replay/conflicting IDs across restart; browser selection, persistence, capability text, pending request freeze, keyboard/mobile layout and existing conversation regression.


The composer keeps the compact model selector immediately left of Send on one
non-wrapping row at desktop and mobile widths. Long display names truncate instead
of moving above Send; both controls retain a 44px target. Layout does not change
model selection or the selected-model snapshot of an in-flight request.
